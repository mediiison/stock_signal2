# Inventory Simulation

Монте-Карло модель управления запасами. Помогает подобрать точку заказа (в днях запаса) для политики с непрерывным контролем остатка и сравнить её с аналитической оценкой. Логическое продолжение `wb_stock_signal`: там пороги запаса заданы вручную (7 и 14 дней), здесь они подбираются по стоимости и уровню сервиса.

## Модель

- Спрос в день: распределение Пуассона, если разброс не превышает среднее, иначе отрицательное биномиальное (перегруженный спрос, характерный для маркетплейсов).
- Срок поставки: нормальное распределение, округлённое до целых дней, минимум 1 день.
- Политика (s, S): когда складская позиция (остаток плюс заказанное в пути) опускается до точки заказа `R`, делается заказ до уровня `R + цикл`.
- Непокрытый спрос теряется (lost sales), как при отсутствии товара в карточке.
- Для каждой точки заказа выполняется `runs` независимых прогонов на `horizon` дней.

## Метрики

| Метрика | Смысл |
|---|---|
| `fill_rate` | доля спроса, покрытая из наличия |
| `stockout_day_share` | доля дней с дефицитом |
| `avg_inventory` | средний остаток на складе |
| `orders_per_run` | число заказов за горизонт |
| `avg_cost` | средние суммарные затраты: хранение + потерянные продажи + заказы |
| `cost_p95` | затраты в 95-м перцентиле (плохой сценарий) |

## Запуск

```bash
python inventory_simulation.py
```

Пример с параметрами и графиком:

```bash
python inventory_simulation.py \
  --mean-demand 20 --demand-std 12 \
  --lead-mean 10 --lead-std 3 \
  --horizon 180 --runs 2000 \
  --cycle-days 14 --target-service 0.95 \
  --plot result.png
```

| Параметр | Описание | По умолчанию |
|---|---|---|
| `--mean-demand` | средний спрос в день | 20 |
| `--demand-std` | стандартное отклонение спроса | 12 |
| `--lead-mean` | средний срок поставки, дни | 10 |
| `--lead-std` | разброс срока поставки, дни | 3 |
| `--horizon` | длина прогона, дни | 180 |
| `--runs` | число прогонов на точку | 2000 |
| `--cycle-days` | дней запаса сверх точки заказа при заказе | 14 |
| `--holding-cost` | стоимость хранения единицы в день | 0.5 |
| `--stockout-cost` | потеря на единицу непроданного спроса | 30 |
| `--order-cost` | фиксированная стоимость заказа | 200 |
| `--target-service` | целевой fill rate | 0.95 |
| `--min-days`, `--max-days` | диапазон перебора точки заказа, дни | 3, 30 |
| `--seed` | seed генератора | 42 |
| `--out` | CSV с результатами | `inventory_simulation_results.csv` |
| `--plot` | путь к PNG с графиком (необязательно) | выключено |

## Что выводится

- Таблица по всем точкам заказа.
- Точка заказа с минимальной стоимостью.
- Самая дешёвая точка, удовлетворяющая целевому `fill_rate`.
- Аналитическая точка заказа `mu * L + z * sqrt(L * sigma_d^2 + mu^2 * sigma_L^2)` для заданного уровня сервиса.

Аналитическая формула считает вероятность не уйти в дефицит за цикл заказа (cycle service level), а симуляция измеряет долю покрытого спроса (fill rate).
